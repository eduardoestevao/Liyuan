# 开场白分册

## 三种开场

- `first_mes`（默认开场）：序号 0，新会话的第一条消息。
- `alternate_greetings[]`（备选开场）：用户切换着用。
- `group_only_greetings[]`（群聊开场）：**梨园没有群聊功能，不消费这个字段**——能列出、能编辑、随导出保留，但开演不会用到。给梨园写卡不需要它。

三种在工程里都是 greeting 资源（`read` / `write` 按资源 ID 编辑，`add kind=greeting` 新增，`group: true` 建群聊开场，`remove` 删除）。

## 切换开场是用户操作

`POST /api/greeting` / `/greeting` 命令切换当前会话用哪条开场，未开聊时还能即时替换对话里的开场白。这不是创作操作——改完应用后告诉用户「新开场对新会话生效；当前会话可用 /greeting 切换」。

## 宏

卡文本里梨园只求值两个宏：`{{char}}` → 角色名、`{{user}}` → 用户名（`src/card-macros.ts`，大小写与空格都容忍）。**其他酒馆宏（`{{random}}`、`{{roll}}`、`{{lastMessage}}` 等）不求值**，原样留在文本里。开场白里见到 `{{char}}` 是正常的；见到别的宏要想清楚它在梨园里就是字面文字。

## 开场的皮肤化

first_mes / 备选开场会在显示侧过显示正则（含 HTML 的会渲染成界面）、送模侧过送模正则。开场白末尾作者手写的 `<StatusPlaceHolderImpl/>` 会被尊重（harness 只在正文里**没有**它时才补挂，见 MVU 分册）。含 `<script>` 的开场（如 E 类全家桶卡）在消息帧内运行，受沙箱限制（见 scripts 分册）。

## 写作上的注意

- 开场是模型每拍都看得到的上下文（历史第一条），长开场等于常驻成本；但它不进 system，进的是对话历史。
- 备选开场为空字符串时（D 类卡有此样本）是空项不是废项，保留。
- 事实细节放进开场白能保证模型第一拍就知道；放世界书绿灯则要先被检索。重要人设宁可写进开场或常驻，不要赌检索。
