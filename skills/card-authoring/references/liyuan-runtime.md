# 梨园运行时分册：一张卡在扮演时经历什么

写卡前知道这些，能避免写出「在酒馆里有用、在梨园里无效」的东西。

## system 是怎么拼的

每拍装配（`src/stage/assemble.ts`），自上而下大致是：遗留预设段 → 用户规矩两级文件（全局→卡级） → 卡内容 → 人设 → 世界书常驻块 → 工具说明。卡内容部分：

- **卡带 AGENTS.md 演出档案**（卡目录下）时：档案文本取代卡的人字段段＋常驻世界书段（一份不双份）。
- 没有档案时走兜底版式：description / personality / scenario / mes_example 进「你扮演的角色」段；常驻世界书（蓝灯）进 `# 世界设定（常驻事实）`；绿灯世界书只进标题索引行（约 2000 字预算），模型用 `lorebook_search` 主动检索全文。
- 预设若填了对应槽位（charDescription / worldInfoBefore / worldInfoAfter 等），卡侧对应段让位。

## 对话循环

- 主循环是原生 agent 会话：模型有工具（世界书检索、场记账本、ask 分岔等），分段写正文走稿纸流程，不是单轮直出。
- **场记（scribe）**：每拍正文定稿后，场记读剧情判断持久变化，写世界状态账本；MVU 卡连变量树一并判断（见 MVU 分册）。你写的世界设定与更新规则最终是给场记读的素材。
- **协议剥除**：第三方插件协议条目（`<UpdateVariable>` 输出要求、`[mvu_update]` 之类）对主模型整条退场——梨园用原生记账通道替代它们。给酒馆插件写的指令协议在梨园既不生效也不需要。
- 显示侧：正文过显示正则进消息帧（沙箱 iframe，脚本可跑，见 scripts 分册）；送模侧正文过送模正则。两侧只认 placement 含 2 的正则。

## 什么不被梨园消费

写这些等于白写（会保真保留，导出酒馆仍有效）：

- 群聊开场（`group_only_greetings`）——梨园无群聊。
- placement 1/3/5 的正则（用户输入、斜杠、世界书变换）。
- EJS（`<% %>` 模板条目）——梨园无 EJS 执行器，只展示。
- 条目的 `position / depth / role / probability`——注入版式归梨园，不看酒馆的插入位置参数。
- 世界书书级字段 `scan_depth / token_budget / recursive_scanning`——检索预算是梨园自己的机制。
- 脚本的 `button / data` 声明（只统计不渲染）。
- 酒馆宏族（`{{random}}` 等）——只有 `{{char}}/{{user}}` 求值。

## 卡目录里还有什么

每卡一个目录（卡空间）：`card.png/json`、`创作/`（你正在改的工程）、`AGENTS.md`（演出档案）、`技能/`（卡级 skill）、会话与记忆目录。卡的 AGENTS.md 是**演出档案**（给扮演模型的常驻内容），不是给你的开发指令；改它要当作改常驻注入内容，影响每拍 system。

## 创作工程在这一切里的位置

`创作/` 工程只管卡文件本身。应用后卡重载，常驻内容、正则、脚本立即换新；已开演的会话里，世界状态账本与变量树**不回溯**——改了设定或初值，已有剧情的事实不会自动重算，需要用户开新会话或你明确提示这一点。
