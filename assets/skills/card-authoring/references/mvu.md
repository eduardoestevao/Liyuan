# MVU 变量分册

MVU 是酒馆生态的变量插件协议。梨园对它做了**兼容但不复活协议**的接管：树归梨园账本，判断归模型（场记），落值由 harness 死板执行。

## 树与初值

- 变量树是 `stat_data` 下作者自定义的任意深结构（键名每卡不同，梨园不认字段名）。会话首用时（懒建、幂等）从卡的初值声明播种，`{{char}}/{{user}}` 宏求值。
- **初值两种来源，按优先级**：
  1. 世界书 `[initvar]` 条目（YAML 式，老形式）——那是作者写的实际初始数据；
  2. 脚本内联 zod schema 的 `prefault` 默认值（`parseMvuSchemaDefaults`，现代卡主流）。
  两者都有时 `[initvar]` 赢。五卡实测零 `[initvar]`，C/E 类卡的初值全在脚本 schema 里。
  3. `tavern_helper.variables` **不参与播种**——那是页面组件自己的数据（E 类卡 4.3KB 的组件状态），outline 里列为 mvu 板块可编辑，但长不出树的初值。

## 更新规则

- 含 `<UpdateVariable>` / `_.set` 的常驻条目是 MVU 的更新规则（`isMvuRulesEntry` 识别）。它们**保留给场记**：场记读完每拍正文，按规则判断这棵树该改哪些值，出平铺 patch，`applyMvuPatch` 套进树。判断在模型，落值在 harness。
- **对主模型，这些规则条目被协议识别器剥除**，主模型不输出 `<UpdateVariable>`。改规则时写清楚语义给场记读，不用担心污染正文。

## 状态栏挂载点（最常误解的一环）

`<StatusPlaceHolderImpl/>` 是 MVU 插件发行的全生态逐字相同的协议常量，**模型从不输出它也看不见它**。真实链路：

1. 卡的显示正则里有一条「整条正则恰好就是这个字面量」（isMvuPanelMount 判据，差一个元字符都不算）；
2. harness 在**最新一条**正文末尾补挂这个占位符（正文里已有则不补；开场白里作者手写一个，那时不补）；
3. 显示正则把占位符换成整份面板 HTML；
4. 面板脚本轮询 `getAllVariables().stat_data` 重画。

所以：**不要把占位符写进正文稿**；要卡有 MVU 状态栏，需要三件套——schema/初值、显示正则（find=字面占位符）、面板脚本。只补其中一件，面板是黑的。
梨园只持有一棵当前树，只补最新一条消息：拿当前值画历史消息的面板等于对历史撒谎，不做。

## 卡级变量初值的编辑

outline 里「卡级变量初值」项（`tavern_helper.variables`）的 `meta` 走 `fields: { value: {…整对象} }` 整体替换。改 `stat_data` 初值请改 `[initvar]` 或脚本 schema；已开演的会话树不回滚（树随剧情演进，是 f(分支) 的权威，重开会话才重新播种）。

## 预览变量

`preview` 的 `variables` 参数直接覆盖测试树（默认取卡内初值），不落任何真实账本——试验数据放预览里，别写进剧情。
