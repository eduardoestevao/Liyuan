# 导出与酒馆兼容分册

导出走角色卡详情的原有入口（`/api/card/export`），导出的是**已应用**内容；创作稿里未应用的改动不进导出。

## 格式与模式

- `format=png / json`。PNG 只换 tEXt 内嵌 JSON，图像像素不动（封面另走 `cover` 操作）。
- `loreMode`：
  - `embedded`：保留卡内原书原样。
  - `active`：合并挂载的独立世界书——保留原书元数据与重复项，活跃修改覆盖同 UID 条目（活跃字段与扩展优先）；用户停用清单在导出时生效（对应条目标停用）。
  - `none`：不带世界书。

## 梨园特有内容不进卡包

- `创作/sections.json`（板块归属声明）——梨园自己的视图数据。
- 结构账本、快照、conflicts——工程内部文件。
- 用户的停用清单只影响导出结果，不写死进卡。

## 修改在酒馆里的有效性

- 条目/正则/脚本按公开卡格式写回，`position / depth / role` 等酒馆字段镜像保留（元数据白名单里改它们时 v2 字符串与 v3 `extensions` 数字同步写），在酒馆里行为与原本一致。
- placement 1/5 的正则、EJS 条目、群聊开场原样保留——梨园不消费，酒馆照常用。
- 你用梨园白名单外字段做不到的事（case_sensitive、group、sticky 等）留在原包不动，导出后仍在。
- `add` 新增的条目/正则/脚本载荷是公开格式的最小完整形状（条目带 id/keys/position/extensions.position 等全套字段），在酒馆里可直接打开编辑。

## 导出前的自检

1. `check` 零错误（语法、结构、账本对得上基线）。
2. `outline section=deps` 看外部依赖：每条都记着来源主机。远程 CDN 的库与图床是运行前提，导出到的环境没网或防盗链就跑不起来；能自包含的尽量自包含。
3. 预览过一遍（`preview`）确认界面在梨园侧渲染正常——注意这不等于在酒馆里验证过；两边差异（placement 消费面、宏族、宿主 API）见各自分册。
