# 回归 pi · 第三刀：RP 工具与稿件工作区

2026-09-07，已落地，改动保留在工作区，尚未提交。用户已批准调查后提出的工具清单，并要求先完成本刀；复杂角色卡的制作与修改另记为一个独立维度，见 [角色卡制作维度](PLAN-CARD-AUTHORING.md)。第一、二刀的未提交工作是本刀基线，不回退或混作本刀成果。

## 本刀契约

- 正文工具：`draft_write`、`draft_append`、`draft_read`、`draft_search`、`draft_edit`、`draft_seal`。
- 拍内计划：`beat_plan` 合并列计划、调整剩余项和勾选；计划是假设，允许取消，不以全部完成作为收笔门槛。
- 取证：新增 `lorebook_read`、`memory_read`，既有检索返回可追溯引用；`memory_search` 接卡级 Markdown 记忆，保留局与分支来源。
- 技能：`skill_read` 接卡目录的“技能”及引用资料；按需读取，无每轮强制技能。
- 交互：`ask` 之前的正文可见，答案回到同一拍；停止保留已写内容。
- 记忆纠错：补卡级 `memory_update` 和遗忘入口，处理来源、并发与后续合并，避免纠错被旧复盘覆盖。
- 机制：明确探索阶段、真实收笔状态、文件版本与用户撤销、上下文可观测及重复结果剪枝。主循环仍由 pi `AgentSession` 驱动。

## 所有权与边界

问题全集是任意卡上的正文创作、修改、取证和恢复。稿件工作区负责内容与版本，pi 扩展负责既有钩子，场记负责定稿后记账，前端负责同一稿的展示与用户操作。不识别卡作者的标签、姓名或措辞。

正文落在卡的对话子项目内，按会话、分支与拍次隔离；同一版本用于读取、修改、展示和落树。修改采用原文锚定、版本核对与原子批量提交。会话记录保持追加式；用户撤销稿件不是世界线回退。

不恢复 `draft_check`、禁词/字数驱动的末端修稿、每拍 LLM 审稿员或强制分镜仪式。不新增提示词催告、注入席位或作者措辞识别。新工具的描述与返回值承担新增协议，既有系统提示词不加码。世界线回退、新建和切换会话仍属用户端。

对照 `PLAN-ROUND-FLOW.md`：落实“探索与构思 → 写出可见上文 → 按实际剧情与用户回答调整 → 收笔”，保留交互目标；已被后续用户决定撤销的检验器、逐段强制读 skill、查库次数门禁不复活。

## 实施与验证记录

### 1. 稿件与交互

六件正文工具现在操作同一份持久稿件。模型写入、追加、修改、收笔都须带当前整数版本，空稿从 `v0` 开始；过期版本拒绝整次操作。修改按唯一原文锚定，有限的空白/标点放宽会回报匹配级别；任一处缺失、重复或重叠，整批不修改。读取、搜索和版本存档保留原文空白。

卡项目的落点是 `cards/<卡>/对话/<子项目>/稿件/<sessionId>/<beatId>.json`，兼容旧 sessionDir 布局。一个 JSON 原子替换，包含正文、修订、计划、时间线和拍次状态，不再维护一份可能不同步的 Markdown 镜像。文件摘要用于拒绝已发生的外部改动；重新读取后才能继续。

`beat_plan` 支持列计划、改剩余事项、完成与取消。默认处于写作阶段，简单回应无需调用计划；显式进入 `explore` 后，原生 `tool_call` 钩子只放行读、提问与计划，切回 `write` 后恢复写侧。

`ask` 之前的正文先保存和展示，等待回答时仍可查看、恢复版本；答案回到同一拍，并带当前版本。流式正文和未完成的写稿参数保留检查点（约 250ms 及工具边界）。停止或模型出错时保存已接收内容；进程崩溃后可查看最近的磁盘检查点，包括“已有正式版本 + 尚未完成的续写”。

显式写稿后没有 `draft_seal`，会保留稿件并报告尚未收笔，不启动场记。普通直接输出仍可由宿主代收；`explicitWrites` 与 `directWrites` 分别计数。探索阶段的直接输出不会被代收成完成稿。

### 2. pi 原生边界

主模型、工具校验、顺序执行、工具结果和停止仍由 pi `AgentSession` 负责，本刀未另建主循环，也未改动 vendored pi 包。

- `draft_seal` 成功返回原生 `terminate:true`。单独收笔后直接进入现有场记流程，避免再请求一轮主模型。
- pi 0.84.4 的规则是**同批全部工具结果**都带 `terminate:true` 才结束。因此工具描述要求最后单独调用收笔；若与读取等混在同批，pi 仍可能再请求一次，已有原生循环测试覆盖该行为。
- pi 不读取工具 execute 返回对象上的 `isError`；扩展通过原生 `tool_result` 回传真实错误标志。版本冲突等错误不会再被标成成功。
- 实弹中，无必填字段的工具收到了额外的 `_` 占位参数，导致计划和读稿被原生校验拒绝。此类根对象现在允许无作用的额外键；已声明字段、嵌套计划项、带版本的写入仍照常校验。没有添加一条“提醒模型不要传占位参数”的提示词。
- 服务端保留原生工具起止事件，供过程展示与资产缓存失效使用；正文增量和最终展示仍使用稿件的统一投影。

### 3. 来源与记忆

`lorebook_search` 返回内容指纹引用，`lorebook_read` 按引用读取完整原文或字符范围，带来源、启用状态；旧引用失效时明确报错，不用模糊命中替代。

`memory_search` 合并当前分支的会话向量记忆与卡级 Markdown 手册、常驻摘要、各局复盘。返回来源状态，区分无命中、停用、不可用和错误。`memory_read` 按精确引用读取；会话库的搜索、读取和列举都检查分支，空分支集合不再退化成“全部可见”。

卡级引用为 `card:handbook`、`card:resident`、`card:recap:<chatId>`。`memory_update` 按内容摘要校验版本；既有删除入口接入卡级遗忘。修改前备份在卡的 `记忆/.history/`，保留来源身份；纠正源复盘会使未受手工保护的旧汇总失效，遗忘会留下持久标记，后台在途复盘/合并也不能覆盖后来的手工决定。

### 4. 技能、恢复与上下文

技能从全局 `skills/` 与当前卡的 `技能/` 发现；卡内同名技能覆盖全局，卡内停用也会遮盖全局同名项。`skill_read` 按需读取包内引用资料和范围，并检查真实路径边界。管理界面、REST 与助手工具都保留来源 scope，可以分别编辑全局或卡级来源；没有新增默认写作教条。

前端增加本拍稿件面板：计划、阶段、版本原文、用户恢复和上下文字符统计。刷新从 hello 的同一份工作区恢复，不再被随后多余的 start 事件清空。选择卡出现时跟随到底部，确保前文与选项都可见。

恢复版本是用户操作，会新增版本。等待回答时直接作用于当前拍；结束后追加 `rp-draft-revision` 回执，展示与下一拍的历史装配读取同一投影。回执写入中断时，工件里的待完成标记可在重启后补记一次。世界状态和世界线不随文本恢复而回退。

上下文只对重复读取结果和较旧稿件读取结果做确定性剪枝，保留调用配对、用户选择和错误回执，不修改 pi 的原始历史。界面显示的是字符量，不能当作计费 token。

### 6. 当前边界

- 卡级手册/复盘跨局，工具会标明来源；它们不是“当前分支已发生事实”的保证。
- 手工修改聚合手册或常驻摘要会固定该汇总并暂停自动合并；新局复盘仍可单独读取，目前没有额外的解除固定按钮。
- 界面只恢复当前分支的最新一拍；恢复改的是文本，不回退场记账本。进程崩溃后可查看检查点，不会自动重放工具或恢复一条旧模型请求。
- 收笔与其他工具混批时仍遵守上面的 pi 原生终止规则。真实网络时延和供应商故障不由稿件机制消除。
- 本刀补齐的是扮演与正文修订的这组工具和机制；复杂卡的代码、MVU、状态栏制作仍按独立记录另行调查。
