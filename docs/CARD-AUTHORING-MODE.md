# 主会话写卡模式：共享记录与可见范围

2026-09-09，用户明确「那么开始吧」后实施，基于 `5c45fc1` 的未提交工作区。沿用 [资源编辑第一切片](CARD-AUTHORING-SLICE1.md)，写卡的主要入口改为当前主会话。用户常用的 7620 服务未重启，改动尚未提交、推送或发布。

## 用户可以怎样使用

在同一条对话里提出制作或修改角色卡、前端、脚本的要求，主模型可以调用 `conversation_mode` 自行进入写卡模式；顶栏副标题有手动两段开关「扮演 | 工作」。生成期间的手动切换暂不可用，停止后可切换。

> 2026-09-12 更名：模式的界面叫法从「写卡」改为**「工作」**（用户定：这个模式承担一切要动代码与文件的任务，不止写卡）。模式 id、`assets/AUTHORING.md` 与本文其余措辞仍是「写卡/authoring」，语义不变；其余文档措辞待收尾统一。

写卡模式能够查看本会话当前分支的剧情及原始操作记录，调用卡片资源服务和原生文件工具。已有卡的复杂资源仍通过「角色卡 → 代码与资源」查看、编辑、检查与预览；`card_project` 与该面板使用同一份服务。简单卡字段也可用 `card_update` 修改。

应用后，卡片与前端素材在当前会话重载。模型切回扮演时结束本次维护，下一条用户输入接着原剧情演。界面保留带「写卡」标记的请求和报告；它们不会进入后续扮演上下文、场记、剧情摘要或剧情记忆。即使最初从扮演模式提出修改要求，该条触发请求也会随切换归入写卡。

## 一份底层记录，按模式选择可见内容

仍只有主会话原有的 `AgentSession` 和 `SessionManager`。不另开写卡会话，不复制两份历史，不使用意图分类模型或关键词路由。右栏助手保留为独立入口，主会话不再自动委托 `assistant_run`，也不因 `//` 或括号输入自动打开助手。（2026-09-12 追记：右栏助手已整体删除，见 PLAN-SANDBOX.md 第六节。）

| 记录 / 视图 | 作用 |
|---|---|
| `liyuan-mode` | 在原会话树追加模式、来源及触发请求 ID；支持重开与分支恢复 |
| `liyuan-process` | 按原生消息保存 assistant、toolResult、工具参数和回执；两个模式的操作都记录 |
| `details.liyuanMode` | 标记从写卡模式提交的用户消息和写卡展示消息 |
| `authoringHistory` | 重放当前分支已保存的原始对话与工具交换，不走扮演清洗、作者显示正则或剧情摘要裁切 |
| `storyBranch` | 排除属于维护请求的整个片段，供扮演、场记相关状态、摘要、上一拍定位与剧情记忆共用 |
| `displayConversationBranch` | 仅为显示补充归属标记，不篡改最初的用户记录 |

扮演仍按既有机制使用定稿、故事状态和前情摘要。写卡时重新开放底层保存的操作内容，回到扮演后再次封闭，记录本身不删除。展示报告与媒体展示副本不会重复回放为工具交换。旧版仅保留文本诊断的操作，以「旧会话操作记录」展示给模型，不伪造成原生调用。

## 原生循环与工具范围

模式切换工具在两种模式中都可见。模型进入写卡后，在同一次原生运行的下一次 provider 请求中更换 system prompt、可见历史和活跃工具。运行时新增 `setTurnSystemPrompt`，复用现有下一轮上下文准备逻辑；没有新增模型/工具循环。

写卡工具包括可用的卡服务、原生 `read / bash / edit / write / grep / find / ls`、已安装资料的 `skill_read` 和当前启用的 MCP 工具。`backendControl: false` 时不开放原生文件工具。没有注入宿主实现的工具不会出现在清单里。写卡提示词在 `assets/AUTHORING.md`；卡内 `AGENTS.md` 是创作素材，不改变写卡模型的工作身份。

维护轮不提供剧情稿纸、场记或剧情记忆写入工具，结束时不自动执行场记、入库、存档或剧情压缩。退出写卡后，同一工具批次中剩余的写操作也被拦住；主动切回不会被展示成用户中止。

刷新发生在原生会话结束、连接释放后，排队请求开始前。队列保存提交当时的模式，前一轮切回扮演不会把已经提交的维护请求改成剧情。鉴权等待和流式生成期间停止，都保留正确归属；磁盘重开仍可恢复。

只有原生运行时确实注册、且按相同规则解析的斜杠命令才走命令通道。路径、未知命令、`//` 等普通输入继续走当前模式，避免未经投影的裸生成。回退、删除回复、编辑回复和变体导航只定位剧情用户轮；原始过程及面板等元数据不会挡住变体发现。

## 前端与实时维护

模式由服务端推送并随 `hello` 重连恢复。写卡流式输出、报告及停止残留都走普通 Markdown/代码文本显示，不把示例 HTML 挂成真实卡界面。维护消息不占剧情楼层、不参与作者正则的剧情深度计算，也不提供会误改剧情的用户轮编辑/删除入口。

正式卡界面继续使用已应用的卡资源；工作稿的预览仍采用第一切片的独立测试变量与消息桥隔离。浏览器验证中，修改状态栏模板并应用后，同一会话已显示的剧情界面更新为新布局，代码示例未被执行；无需创建另一条故事。
