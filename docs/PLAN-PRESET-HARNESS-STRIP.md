# 预设剥离 harness：编译后窄拆契约

> **2026-09-12 终态（用户定序，见状态末三条）**：预设的处理是一条四步管线——
> ① 导入 JSON 原样复现（预设库） → ② 装载后在块编辑器里拨开关（人称/基调/文风等选项就是块的 enabled）
> → ③ 引擎 `assemble()` 按开关编译成一份提示词 → ④ 梨园二次处理：模型逐段声明站别（按块留档，拨开关不重问）、分流成逐块 `（预设）` 条目
> （身份→卡级 APPEND_SYSTEM.md，写作→卡档案 AGENTS.md，机制段→档案里的关闭条目，包装跳过）。
> **③④ 全自动，没有手动转译**：装载就转译、拨开关/保存/还原就重转译、卸载就剥净、换卡按新卡重落（`server/rest.ts syncPresetTranslation`，挂在 `softRefreshConfig`）。
> 预设保持装载（采样参数、作者正则仍从它取），但**台上不再直接吃它**（`materials.ts`）——模型看到的就是那两份文件。
> 选项在 ②/③ 由引擎带开关重跑取得；④（`src/preset-declare.ts`）**不读未启用块、不手搓宏求值**——那是上一个窗口被点名的开倒车（`7392c40`，已随 `faa519e` 回退）。
> 同日补齐：条目来源标注扩到世界书（`（世界书·书名）`）——挂载书的蓝灯**镜像**进卡档案：挂上就有、卸下就没、新增/改动跟着来（同一套同步）。
>
> （此前 `faa519e` 曾整体回退窄拆机制——回退的是「从 JSON 直接造条目」的形态，不是方向；保留的无关副产物：cpSync 崩溃修复（`src/fs-copy.ts`）、prompt-entries 的 CRLF 解析修复、预设库装载/保存按钮、块编辑器来源标注。）
> 本档留作实验记录：甲乙数据（`.liyuan-artifacts/preset-ab/`）与 13 份编译分析（`.liyuan-artifacts/preset-compiled/`）仍在，结论未被推翻——是形态不被接受（转译进卡文件这条路用户不要了），不是方向被证伪。10/11 点名的「setvar 型选项是变量开关、文件形态表达不了、手搓求值＝开倒车」是真教训：**未启用块的正确处理方式只有让引擎带开关重跑取差异，任何绕开引擎的求值都违 8/16 定纲。**


## 一、为什么这次能成（上次 8/14 死在哪）

- 8/14 死的是**判断载体**：对 242 个不透明 JSON 块做性质分类，208/242 落兜底；块名是作者词汇表（铁律三不许认）。
- 本次载体换成**编译后全文**：梨园装配器（`assemble()`）跑一遍，得到模型真正看到的 1~2 万字线性文档。8 个作者的预设编译后共享同一套「站点语法」，且作者用自声明标签（`<thinking_rules>`、`<main_output_format>`、`<writing_process>`…）把站点划清楚了。
- 溯源现成：装配结果逐 piece 带块 identifier，段落级声明可精确落回 `prompt_order[].enabled`（酒馆自己的开关，合法数据通道）。

## 二、编译后站点语法（13 份实测归纳）

```
[身份/破限] → [材料包装] → ⟦历史⟧ → [写作规则] → [思考协议] → [输出合约] → [assistant 预填]
```

| 站点 | 预设模拟的机制 | 梨园的真身 | 处置 |
|---|---|---|---|
| 身份/破限（含信件对） | 角色身份 | 梨园身份（分层共存） | **卡级 APPEND_SYSTEM.md** |
| 写作规则（文风/边界/nsfw/精神分析） | — 纯话 | — | **卡档案 AGENTS.md**（材料槽，弱约束） |
| 材料包装 + marker 槽位 | 上下文装配 | 梨园装配器 | **不动**（编译器本职） |
| 思考协议（思考模板/地板/` drastically 禁令`） | 规划-检查循环 | agent 循环 + 原生思考 | **停用** |
| 草稿协议（段前注释排练） | 迭代写作 | draft_append / draft_seal | **停用** |
| 输出合约（strict_format / w2g / fox_selc / StatusBlocks / safe 仪式） | 结构化输出 + UI 数据层 | MVU + 面板 + ask + 渲染管线 | **停用** |
| 记忆记账（summary / key_memory） | 状态记账 | 场记 + world_state + 摘要 | **停用** |
| 末条 assistant 预填 | 输出引导 | 已按 8/23 定案丢弃 | 现状即终态 |
| samplers | 采样配置 | config.samplers | 数据侧（转译已做） |
| 顶层 harness 字段（43~45 项） | 引擎行为 | 未消费 | 原包保真，如实报告 |

### 槽位语义（三分法，2026-09-12 用户定案）

- **SYSTEM.md = 引擎协议**（梨园自己发行：消息流约定、MCP 外设、工具纪律）
- **APPEND_SYSTEM.md = 身份契约**（预设身份 + 破限；强槽）
- **AGENTS.md = 这张卡的全部**——世界 + 写法（写作规则弱约束入此，与卡作者末端指令同一家）

## 三、流程（窄拆五步）

1. **编译**：`assemble()` 跑一遍预设 + 当前卡材料，得全文 + 逐块溯源。
2. **声明**：模型读编译全文，逐段声明站点类别（上表六类 + 破限 + 包装）；**拿不准一律留，破限一律不碰**。声明落数据（每段 → 块 identifier → 处置）。
3. **过目**：用户看声明清单（每份预设十来个段落的清单，不是 250 块），可改可否。
4. **落盘**：转译分流——身份→`cards/<卡>/APPEND_SYSTEM.md`，写作规则→卡 AGENTS.md 新板块，停用清单→`prompt_order[].enabled` 或转译报告。原文留 `assets/presets/` 永不改动。
5. **验证**：甲乙双配置实验（同卡同输入同模型）：甲＝剥离后、乙＝整份。量四样：思考量 / 工具使用 / 嗓子 / 正文落法。

## 四、铁律自检

- 铁律一：送模文案只减不增（停用即减）；不加任何催告。
- 铁律二：不新增注入点——身份/规则落既有文件槽，停用走酒馆 `enabled` 开关，声明走既有转译通道。
- 铁律三：判断权在模型（声明一次）+ 用户（过目），落成可见数据；不建块名名单。
- 铕律四：全集＝任意编译后文档的段落；负责人逐站明确（每站有梨园原生主人）；未见过的卡＝声明拿不准就留，下行有界（最差＝今天）。

## 五、已知代价（认下，不当 bug 查）

1. 每份预设过用户一眼（这次看的是段落清单，不是 250 块）。
2. 停输出合约后，靠预设教模型吐状态栏的卡会停止吐——梨园里这是预期行为（MVU/面板接管）。
3. 破限信件对转译后被拍平成文件内引文（role 弱化）；保真 role 需新注入通道，违律二，不做。
4. 转译按卡落（宏必须在卡上求值）；换卡、预设更新都触发重转，触碰用户手改过的 AGENTS.md 时列为冲突不静默合并。
5. AGENTS.md 一落盘卡即进文件模式（刀3 规则），面板改字段不再反映到档案。
