# RP 上一拍修订：实现与验收

2026-09-07 晚实施，2026-09-08 收尾。改动保留在工作区，未提交；第一至第三刀的既有改动不回退。

**上一拍修订通路已完成。** 主演可以读取并修改当前分支上一拍的已定稿回复，修改落回原回复位置，界面和后续上下文使用同一版本。小说模式的任意章节编辑、复杂角色卡制作仍延期。

## 工具与边界

| 工具 | 作用 |
|---|---|
| `previous_draft_read` | 读取上一拍精确原文、版本及该拍真实的用户选择；支持 UTF-16 范围读取 |
| `previous_draft_edit` | 按读取版本和唯一原文引用批量修改；成功即结束本次修订请求 |

- 目标由当前分支确定，不接受任意历史 ID。没有上一拍、上一拍尚未收笔、读取后目标/版本变化时拒绝操作；不越过停止稿去改更早的拍次。开场白不作为已完成的主演回复。
- 原文引用缺失、重复、重叠或版本冲突，整批不改。未引用的文本原样保留；不允许清空整篇。已有本拍新稿时不能同时回改上一拍。
- 旧回复没有第三刀稿件文件时，仍可从分支正文建立版本；兼容用户手改回复与旧的追加补丁，旧补丁不会在全量修订之后再次执行。
- 修订是**正文操作**。不推进剧情，不重跑场记，不触发一次新的剧情入库，不回退世界线；不会自动重算账本、MVU、面板数据或已存记忆。修改既定事实后的关联数据协调仍未实现。

## 落点与所有权

问题全集是任意卡上的上一拍成稿修订；负责人是稿件事务与分支历史投影。对没见过的卡仍只处理自有协议、版本和原文，不识别作者名字、场景标签或措辞。

为了避免共享祖先稿件污染兄弟世界线，修订采用写时复制：原稿文件保留，当前分支取得带完整版本记录的修订稿，追加 `rp-draft-revision` 将**同一个回复条目 ID**指向该稿。物理稿件文件 ID 可以变化，界面不会新增一份剧情回复。分支列表只呈现当前生效的稿件。

稿件先原子持久化，再同步会话回执。中断留下的同步标记可在原分支恢复，回执去重；发布前另核对会话、目标和修订请求归属。原始会话正文不重写。

引擎返回 `revisedEntryId`，与新剧情的 `entryId` 区分。原生 pi `AgentSession` 继续独占模型及工具循环；没有修改 vendored pi、另造循环或引入审稿模型。混合工具批次仍遵守 pi 的终止语义，额外直出不会变成新剧情，轮数安全阀继续有效。

完成的修订请求保留在显示历史，并有“上一拍已修订”记录；后续剧情上下文不再携带这些办事指令。压缩和跨局复盘的剧情拍数也不把它们重复计入。

对照 `PLAN-ROUND-FLOW.md`：用户作出的选择和已经完成的正文都有可追溯归属，演员可以修正上一拍后接着演。没有恢复旧的逐段强制流程、字数/文风检查、催告或注入席位。

## 实弹发现与修复：ask 回答不能随工具过程丢失

首次实弹，模型已经自主调用新工具，却提交了两处修改：润色第一句，同时显式删除后半段，674 字变为 367 字。工具执行成功，但用户意图未通过；失败记录保留。

核对实际 HTTP 请求发现：成稿全文在，**上一拍 `ask` 的真实用户回答没有进入跨拍历史**。后半段原本来自用户选择“改道回档案室”，后续模型却看不到这份用户输入。只补改稿工具还不够。

修复保留输入事实：

- 新拍将 `ask` 的问题、回答持久化到稿件 `choices` 与成稿 `rpChoices`。
- 重建历史时，将实际回答归到原拍的用户输入中；不增加一条剧情拍，也不改写原始 user 记录。
- 旧拍从与原回复直接相连的 `rp-text-debug` 中恢复回答，仅解析本项目既有 `ask` 调用与回执协议，不从正文猜测用户意图。
- 上一拍读取工具同时返回这些已发生的用户选择，修订保留它们。

随后用已有恢复入口把**同一份 674 字原稿**恢复，再提交完全相同的自然语言改稿要求。真实请求已包含原用户选择，这次只改第一句，后半段完整保留。系统提示词、轮次催告、内容审查规则均未增加。

## 验证结果

改前 715 项测试，713 通过；最终 **729 项，727 通过，仍是相同的两项既有失败**。新增 14 项覆盖精确修改、并发与分支、旧回复、旧补丁、连续修订、选择归属、停止、回执中断恢复、发布时切换分支及上下文/压缩。

两项既有失败：

1. `实卡: first_mes/备选开场白 一律 html 皮肤、零 status 段`
2. `实卡：初值只写在 schema prefault 里的卡能被播种`

前端类型检查和生产构建通过。后端广域 TypeScript 检查仍有 **33 条既有诊断**；按文件、诊断内容和次数比较，没有新增，不能称为全绿。

官方 DeepSeek 无预设实弹，正式复验 4 个自然输入：

| 用例 | 结果 | 耗时 |
|---|---|---|
| 修改原稿第一句 | 674 → 678 字，v5 → v6，单个引用，后半段逐字保留 | 8.0 秒 |
| 连续再次润色第一句 | 678 → 671 字，v6 → v7，仍为同一回复 | 16.5 秒 |
| 接着演 | 正常产生新一拍，352 字，场记正常执行 | 21.2 秒 |
| 修改新的上一拍 | 352 → 332 字，v1 → v2，目标正确推进到新回复 | 4.9 秒 |

三次修订各自主调用 `previous_draft_read`、`previous_draft_edit`，没有点名工具或规定调用次序。原回复、磁盘稿件与显示投影一致；没有新增剧情气泡，没有新场记快照或修订旁路调用。续演的真实请求含完整 671 字修订稿，旧改稿指令已经退出；重连收到相同正文与稿件身份。

正式复验 9 次成功工具调用、9 次主请求、1 次续演场记。包含首次失败试验与后台工作，共 **24 次实际请求：Pro 20 次、Flash 4 次、Claude 0 次**，均为官方端点、HTTP 200。主模型 `deepseek-v4-pro` / `low`，旁路与助手配置 `deepseek-v4-flash`。这是有限样本的机制与自主采用验收，不代表模型对任意修改要求都会理解正确。
